# 읽기 쉬운 Telegram 장 마감 다이제스트 설계

- 작성일: 2026-07-28
- 상태: 사용자 설계 승인
- 범위: 16:10 Telegram 장 마감 다이제스트의 표시 형식

## 1. 목표

현재 장 마감 다이제스트는 내부 JSON 키, UTC 시각, 기술용 idempotency key를
그대로 노출해 운영자가 핵심 상태를 빠르게 읽기 어렵다. 저장·재시도·보존
계약은 유지하면서 다음 정보를 한국어 요약으로 표시한다.

- 시장 데이터 수집·스코어링·AI 분석 상태
- 시장 국면과 최종 진입 후보 수
- 매수·매도 주문 수, 관리 포지션 수, 실현손익
- 계좌 스냅샷 조회 상태
- 확인이 필요한 누락·장애
- 다음 19:00 데이터 수집 일정

## 2. 범위 밖

- 수집·스코어링·AI 분석·종목 선정 알고리즘 변경
- 계좌를 다이제스트 시점에 추가 재조회
- 거래·주문·체결·손익 계산 변경
- 다이제스트 생성 시각, catch-up, idempotency, sender retry 변경
- payload schema version 또는 DB schema 변경
- 기존에 전송·보존된 다이제스트 본문 재작성

## 3. 표시 원칙

### 3.1 환경

`run_environment`는 시장 데이터가 가짜라는 뜻이 아니라 주문과 Telegram을
실행하는 운영환경이다.

- `mock` → `모의투자`
- `real` → `🚨 실전`
- 그 외 값은 기존 DTO 검증에서 거부한다.

기술용 `digest:{environment}:{date}` idempotency key는 DB 감사 기록에
보존하되 사용자 본문에는 표시하지 않는다.

### 3.2 시간과 날짜

- 제목 날짜는 `YYYY년 M월 D일`로 표시한다.
- 사용자 본문에 UTC ISO 시각을 노출하지 않는다.
- 파이프라인 기준일은 `M월 D일`로 표시한다.
- 내부 `as_of`는 payload와 감사 기록에 유지하되 기본 본문에서는 숨긴다.

### 3.3 정상과 장애

- 정상 상태는 고정된 한국어 라벨 한 줄로 축약한다.
- 누락·실패가 있을 때만 `⚠️ 확인 필요` 절을 표시한다.
- 실패 원문이나 외부 응답은 표시하지 않고 허용된 필드명을 한국어 문구로
  변환한다.
- 동일 경고는 한 번만 표시한다.
- 알 수 없는 상태·국면·필드는 추측하지 않고 `확인 불가`로 표시한다.

## 4. 메시지 형식

정상·부분 실패를 포함한 대표 형식은 다음과 같다.

```text
📋 장 마감 다이제스트 · 모의투자
2026년 7월 28일

📊 오늘의 분석
데이터 수집      완료 · 기준 7월 27일
종목 점수 계산   완료 · 2,519종목
AI 분석          완료 · 위험회피
최종 진입 후보   없음

💼 자동매매
매수 주문        0건
매도 주문        0건
관리 포지션      0개
실현손익         0원 (추정)

💰 계좌
계좌 스냅샷을 조회하지 못했습니다.

⚠️ 확인 필요
- 거래 실행 기록 없음
- 계좌 스냅샷 조회 실패

🕖 다음 일정
오늘 19:00 데이터 수집
```

### 4.1 파이프라인 매핑

| 저장 필드 | 사용자 표시 |
|---|---|
| `collection_status=done` | 데이터 수집 `완료` |
| `scoring_status=succeeded` | 종목 점수 계산 `완료` |
| `analysis_status=succeeded` | AI 분석 `완료` |
| `candidate_count` | 종목 점수 계산 대상 수 |
| `pick_count=0` | 최종 진입 후보 `없음` |
| `pick_count>0` | 최종 진입 후보 `{N}종목` |
| `market_regime=risk_on` | `위험선호` |
| `market_regime=neutral` | `중립` |
| `market_regime=risk_off` | `위험회피` |

알려진 성공 상태가 아니거나 기준일이 없으면 해당 줄을 `확인 불가`로 표시하고
경고 절에 관련 누락을 추가한다.

### 4.2 거래 매핑

| 저장 필드 | 사용자 표시 |
|---|---|
| `entry_order_count` | 매수 주문 |
| `exit_order_count` | 매도 주문 |
| `current_position_count` | 관리 포지션 |
| `realized_pnl` | 실현손익 |
| `realized_pnl_confidence=estimated` | `(추정)` |
| `realized_pnl_confidence=exact` | 별도 꼬리표 없음 |

손익 금액은 천 단위 쉼표와 `원`을 사용한다. 음수는 기존 정수 부호를 보존한다.
주문·포지션 수는 음수가 될 수 없으며 손상 값은 `확인 불가`로 표시한다.

### 4.3 계좌 매핑

- `source=unavailable`이면 `계좌 스냅샷을 조회하지 못했습니다.`로 표시한다.
- 사용 가능한 경우 예수금, 보유주식 평가, 평가손익, 실현손익을 기존 계좌
  의미와 동일하게 서로 분리해 표시한다.
- 검증된 전체 총자산 값이 없으므로 임의 합산하거나 `총자산`으로 표시하지 않는다.
- 일부 필드가 실패하면 사용 가능한 금액은 표시하고 실패 필드만 경고에 남긴다.

### 4.4 경고 매핑

허용된 `failed_fields`와 상태만 고정 한국어 경고로 변환한다.

- `collection` → 데이터 수집 결과 없음
- `scoring` → 종목 점수 계산 결과 없음
- `analysis` → AI 분석 결과 없음
- `trade_runs` → 거래 실행 기록 없음
- `account_snapshot` → 계좌 스냅샷 조회 실패

알 수 없는 필드는 원문을 외부로 노출하지 않고 `일부 상태 확인 불가`로
통합한다.

## 5. 데이터 흐름과 호환성

`Digest.payload`의 version 1 구조는 유지한다. `Digest.body`와
`render_retained_digest()`가 같은 순수 presenter를 사용해 새 자동 메시지와
payload 기반 호환 검증이 어긋나지 않게 한다.

실제 `/digest` 명령은 저장된 sent delivery part를 그대로 복제한다. 따라서:

- 변경 배포 이후 생성된 다이제스트는 새 형식으로 자동 발송되고 재조회된다.
- 배포 전에 생성돼 24시간 보존 중인 다이제스트는 당시 구형 형식 그대로
  재조회된다.
- formatter 변경이 과거 전송 원문이나 part 순서를 바꾸지 않는다.

## 6. 오류 처리와 안전

- presenter는 broker, SQL, Telegram adapter를 호출하지 않는 순수 함수로 둔다.
- payload 허용목록과 민감정보 차단 규칙을 유지한다.
- 계좌 조회 실패를 금액 `0원`으로 바꾸지 않는다.
- 내부 예외·JSON·UTC 원문·idempotency key를 사용자 본문에 노출하지 않는다.
- 본문은 기존 Telegram plain-text 분할과 4,096자 상한을 사용한다.
- 표시 실패는 기존 digest 생성 실패 경계로 전달하며 불완전한 본문을 전송하지
  않는다.

## 7. 검증

다음 회귀를 추가한다.

- mock·real 환경 한글 표시
- 정상 파이프라인·거래·계좌 형식
- `risk_on`, `neutral`, `risk_off` 한국어 매핑
- 후보 0개와 복수 후보 표시
- 음수·양수 손익, exact·estimated 신뢰도
- 계좌 전체 실패와 부분 실패
- 알려진 경고 중복 제거와 알 수 없는 필드 fail-closed
- UTC·JSON·다이제스트 ID가 본문에 없는지
- 새 `Digest.body`와 version 1 retained renderer의 동일성
- 기존 `/digest` 원본 delivery part 재전송 계약 유지
- 전체 Telegram 알림·lifespan·비라이브 회귀

## 8. 배포와 수용

코드 배포 후 다음 정상 16:10 다이제스트에서 새 형식을 확인한다. 실제 수용은
자동 생성된 모의환경 다이제스트와 읽기 전용 `/digest`만 사용한다. 계좌·분석·
주문을 수동 재실행하거나 제어 명령을 호출해 수용 데이터를 만들지 않는다.
